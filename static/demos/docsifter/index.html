DOCSIFTER / 中文技术文档审校

守住代码与结构，
把文字问题筛出来。

DocSifter 取名自 sift（筛选）：审校前先分清边界，把技术内容留在原位。

代码块、SQL、API 参数与技术专词原样保护；错别字、语病与排版问题逐条定位。

01 / 本地初筛规则 + 本地小模型→02 / 按需复核复核修改 · 排查上下文→03 / 反馈闭环记录误报 · 后续过滤
向下滚动，查看审校流程如何展开
01 / 结构隔离

隔离代码与标记，
只审需要阅读的正文。

SQL 代码块、配置项与块内注释整体保护；
Markdown 与 AsciiDoc 标记和正文分开，
只检查真正需要阅读的文本段落。

代码与配置不送审 · 保护标记结构 · 保留原始行号
02 / 规则 + 本地审校

确定问题交给规则，
语境错字交给本地模型。

确定性的词汇和表达问题先由规则处理，
语境相关的错别字再在本地检查。
每条建议都能回到原文件行号核对。

规则示例：登陆 → 登录 · 语境示例：数椐库 → 数据库
03 / 大模型按需复核

复核修改建议，
排查跨行上下文冲突。

第一层逐条核对初筛建议，确认是否必要、是否改变原意；
第二层跨行阅读，排查表述冲突、术语漂移与引用疑点。

按需开启 · 支持自托管或 OpenAI 兼容接口
可限定检查文件与预算上限 · 外部异常不影响本地主流程
04 / 误报反馈闭环

人工标记误报，
后续审校自动过滤。

在报告中标记的误报会保存到本地，
并在后续审校中自动过滤；这些记录还可统一导出，
作为质量基准或离线微调样本。

误报记录本地保存 · 后续运行持续生效 · 支持导出团队样本
05 / 本地优先 · 成本可控

文档留在本地。
基础审校不用云端 API。

规则与本地审校承担日常批量检查，模型就绪后可离线运行。
未配置远端端点时，文档内容不会离开本机。

06 / 融入 Docs-as-Code

全量扫描建基线，
PR 增量守住每次变更。

支持 CLI 本地预检、Web UI 批量审校与 GitHub Webhook 增量检查。
每条建议均保留来源、规则 ID 与原始行号，工具辅助排查，决定权始终在人。
